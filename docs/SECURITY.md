# Безопасность

## Как лучше публиковать панель

Рекомендуемый вариант — держать 3WG Panel на localhost и отдавать наружу только через HTTPS reverse proxy:

```text
127.0.0.1:18080 -> Caddy/Nginx -> Internet
```

Не открывайте панель напрямую на `0.0.0.0`, если точно не понимаете последствия.

## Пароли и secrets

- Используйте сильный `PANEL_PASSWORD`.
- Используйте случайный `SESSION_SECRET`.
- Держите `.env` с правами `600`.
- Не коммитьте `.env` в Git.

## API-ключи

- Создавайте API-ключи только для доверенных интеграций.
- Передавайте ключ через header `X-API-Key`, не через query string.
- Удаляйте ключ, если интеграция больше не используется.
- В базе хранится hash API-ключа, но сам token показывается только один раз при создании. Сразу сохраните его в секретном хранилище.

Подробно: [API_KEYS.md](API_KEYS.md)

## Docker socket

Панели нужен `/var/run/docker.sock`, чтобы смотреть protocol-контейнеры и выполнять команды внутри них. Это высокий уровень доступа. Запускайте панель только на доверенных серверах и защищайте вход в web UI.

## Metrics

Endpoint `/metrics`, `node_exporter :9100` и `cAdvisor :8080` раскрывают техническую информацию о сервере, контейнерах и VPN-состоянии. Не открывайте их в публичный интернет без ограничений.

Рекомендуется:

- включать `METRICS_REQUIRE_TOKEN=1`;
- использовать длинный случайный `METRICS_TOKEN`;
- собирать метрики через приватную VPN/management-сеть;
- или разрешить доступ firewall'ом только с IP monitoring-сервера.

## Firewall checklist

Открывайте только необходимое:

- TCP 80/443 для reverse proxy
- UDP ports WireGuard/AmneziaWG
- TCP 18080/9100/8080 только из private monitoring-сети или только с IP Prometheus
- SSH только с доверенных адресов

Не публикуйте наружу SQLite, Docker API и внутренний порт панели.

## HTTPS

Используйте Caddy или Nginx с Let's Encrypt. Пример Caddy:

```caddy
panel.example.com {
    reverse_proxy 127.0.0.1:18080
}
```
