# Смена рабочего IPv4

Раздел **IP сервера** доступен администратору в Core и Easy Core по адресу `/network`.
В Control используйте **IP серверов**. На ноде должна быть установлена версия с этим API
и запущен обновлённый host update runner.

## Порядок действий

1. Добавьте дополнительный публичный IPv4 у хостера и настройте его на сетевом интерфейсе
   сервера с сохранением после перезагрузки. Основной IP удалять не требуется.
2. Измените DNS A-записи домена панели и VPN endpoint на новый IP. Дождитесь обновления
   DNS. Старые записи в `/etc/hosts` также могут мешать проверке.
3. Откройте **IP сервера**, выберите назначенный адрес и нажмите **Проверить**.
4. Проверьте адрес и список VPN-контейнеров, нажмите **Применить IP**.
5. Проверьте панель через новый IP и VPN с переподключённого клиента. Нажмите
   **Подтвердить соединение** в течение 180 секунд. Можно подтвердить и из Control.
6. Без подтверждения host runner выполнит откат в течение 15 секунд после истечения
   срока. Кнопка **Откатить** возвращает прежнюю настройку немедленно.

## Что меняется

- Домен, ключи, внутренние адреса клиентов и UDP-порты сохраняются.
- Дополнительный адрес используется для исходящего IPv4 VPN-контейнеров через SNAT.
- Входящие службы с публикацией на всех IP принимают подключения на новом адресе.
  Привязанные к конкретному IP VPN-порты не поддерживаются: проверка остановит операцию.
- Основной IP, default route хоста, SSH и адреса сетевых интерфейсов не изменяются.
  Старый IP остаётся доступен для служб, слушающих все адреса.
- IPv6 и DNS AAAA-записи эта операция не меняет.
- Уже открытые соединения могут сохранять старый исходящий IP до переподключения
  из-за conntrack. Панель не сбрасывает соединения других служб.

## Резерв и восстановление

Перед применением создаётся закрытая копия `.env` в `backups/network/`.
Активный IP и срок подтверждения хранятся в `data/network-ip.json` с правами `600`.
Host runner восстанавливает подтверждённые правила после перезагрузки и обновляет их
при смене Docker-адресов контейнеров. Используется отдельная цепочка NAT этой установки;
общие правила firewall не очищаются.

Откат возвращает прежний SNAT и значение `VPN_EGRESS_IP`. Изменённые вручную DNS-записи
панель откатить не может: при необходимости верните их у DNS-провайдера.
Проверка DNS выполняется системным резолвером сервера, поэтому учитывает `/etc/hosts`.
Публичную доступность, внешний firewall хостера и корректность IP на стороне хостера
нужно подтвердить реальным подключением перед сохранением.

Схема рассчитана на Linux, IPv4, iptables и VPN-контейнеры с собственными bridge-адресами.
Docker host/none/shared network mode и IPv6 SNAT не поддерживаются.

## API

- `GET /api/node/network` — адреса хоста и состояние.
- `POST /api/node/network/preview` — проверка `{ "ip": "PUBLIC_IPV4" }`.
- `POST /api/node/network/apply` — применение `{ "ip": "PUBLIC_IPV4", "confirm": "NETWORK" }`.
- `POST /api/node/network/confirm` — сохранение выбранного IP с теми же полями.
- `POST /api/node/network/rollback` — откат `{ "confirm": "NETWORK" }`.

Все операции требуют прав администратора. Изменения записываются в аудит.
Прямой доступ к host runner ограничивается Unix socket установленной панели.
