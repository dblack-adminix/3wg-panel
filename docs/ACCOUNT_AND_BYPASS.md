# Пароль администратора и клиентские исключения

## Пароль

В Core и Easy Core основной администратор открывает **Пароль администратора** (`/account`).
В Control одноимённый пункт открывает форму смены пароля самого центра.
Введите текущий пароль, новый (12–1024 символа) и его подтверждение.
После сохранения нужно войти заново: прежние сессии этого администратора становятся
недействительными. Смена требует действующей веб-сессии и недоступна по одному API-ключу.

Новый пароль хранится только в виде PBKDF2-хеша с солью в базе панели или центра.
Исходный `PANEL_PASSWORD` / `CONTROL_PASSWORD` в `.env` больше не принимается после
смены через веб. Обновления контейнера сохраняют пароль, если сохранена база данных.
Не удаляйте базу и учитывайте, что восстановление старого backup возвращает старый пароль.
Пароли не записываются в аудит. API-ключи интеграций и ключ шифрования центра не меняются.

## «Мимо VPN»

Это список исключений для **клиентских** маршрутов. Он не блокирует сайты на сервере.
Core / Easy Core: `/bypass`; в Control: раздел **Мимо VPN** для подключённых нод.
Ноды должны поддерживать API версии v1.11.0 или новее.

1. Добавьте ресурс с понятным названием сайта или приложения.
2. Укажите точные домены (без `https://`, путей и `*`), IP или CIDR-сети.
3. Включите исключения и нажмите **Сохранить и обновить IP**.
4. Панель получает текущие IPv4/IPv6 доменов и вычисляет `AllowedIPs`, исключая их из туннеля.
5. Скачайте новый `.conf` и повторно импортируйте его на каждом устройстве.

Настройка применяется к новым выгрузкам конфигураций всех пиров этой ноды. Старые файлы
на диске не переписываются, ключи пиров и серверный firewall не меняются.
При отключении исключений повторно выгрузите и импортируйте конфигурации полного туннеля.
При изменении адресов ресурсов повторите обновление IP в панели и импорт на клиентах.
Если DNS-проверка не удалась, прежний список сохраняется.

## Ограничения

- WireGuard / AmneziaWG в обычном `.conf` маршрутизируют по IP, а не по имени приложения.
  Название ресурса — метка для группы; все его API, CDN и вспомогательные домены нужно
  включать явно. Поддомены не добавляются автоматически.
- Исключение IP отправляет напрямую **весь** трафик к этому IP, включая другие сайты
  на общих адресах CDN. В интерфейсе можно раскрыть полученные сети перед выгрузкой.
- DNS в разных регионах может возвращать разные IP. Список — снимок, а не динамические
  правила на устройстве. Для постоянно меняющихся доменов требуется клиент с собственной
  поддержкой доменных правил или правил по приложениям.
- `.vpn` содержит обновлённый вложенный конфиг, но приложение может применять собственный
  режим маршрутизации поверх него. Проверяйте фактический маршрут в конкретном клиенте;
  гарантированная область этой функции — `AllowedIPs` в стандартном `.conf`.
- Большие списки могут не помещаться в QR: скачайте файл `.conf`.
- Режим клиента «запретить соединения вне VPN» может блокировать прямой трафик.
  Для исключений настройте его совместимо со split tunneling.
- Функция не гарантирует, что IP VPN-сервера не попадёт в какие-либо списки блокировок.
  Неучтённые домены и старые клиентские конфигурации продолжат пользоваться туннелем.

Ограничения: до 32 ручных групп и 128 ручных записей, 16384 результирующих маршрута.
Начиная с v1.12.2, домены и сети готового каталога не входят в лимит ручного ввода:
готовые категории и сервисы можно выбирать целиком.

## Готовые списки ru-direct (v1.12.0+)

В разделе «Мимо VPN» заранее доступны три источника:

- [Домены ru-standard](https://github.com/kyoresuas/ru-direct/releases/latest/download/ru-standard.domains.txt).
- [IPv4 ru-standard](https://github.com/kyoresuas/ru-direct/releases/latest/download/ru-standard.ipv4.txt).
- [IPv6 ru-standard](https://github.com/kyoresuas/ru-direct/releases/latest/download/ru-standard.ipv6.txt).

Ни один источник не включается автоматически. Откройте вкладку, используйте поиск,
выберите отдельные записи или весь IP-список и сохраните настройки. Ручные ресурсы
остаются отдельно и объединяются с выбранными готовыми записями.
Домены готового каталога проходят параллельную DNS-проверку (до 16 доменов одновременно).
Большой набор может проверяться до трёх минут. При ошибке DNS или превышении срока
прежний профиль сохраняется, а выбранные флажки остаются в форме для исправления.
Большие готовые IP-списки не требуют тысяч DNS-запросов.

«Обновить списки» загружает новые версии каталога, но не меняет сохранённые маршруты
и не активирует новые записи. После обновления проверьте выбор и сохраните его.
Каталог кешируется на сутки; при недоступном источнике используется последняя
успешная копия с отметкой об ошибке. На первом запуске без интернета ручной ввод
продолжает работать. URL источников фиксированы, содержимое проверяется как данные,
а не выполняется как код. Проект-источник: [kyoresuas/ru-direct](https://github.com/kyoresuas/ru-direct).

На момент проверки оба готовых IP-списка вместе дают 6122 маршрута AllowedIPs.
Такие конфигурации импортируйте файлом и проверяйте ограничения своего клиента;
они могут не подходить устройствам с небольшим лимитом маршрутов.

### Группы и сервисы (v1.12.1+)

Каталог разделён на категории: банки, государственные сервисы, платежи, социальные
сети, маркетплейсы, доставка и другие. Раскройте категорию, чтобы увидеть сервисы,
затем сервис, чтобы увидеть конкретные домены или сети. Флажки позволяют выбрать
целую категорию, отдельный сервис или отдельную запись. Поиск работает также
по названиям категорий и сервисов. Частичный выбор обозначается промежуточным флажком.

Сопоставление берётся из [services.json ru-direct](https://github.com/kyoresuas/ru-direct/releases/latest/download/services.json)
и описаний `config/services` исходного проекта. В сетевых списках агрегированная
сеть может пересекаться с адресами нескольких сервисов и отображаться у каждого.
Это одна и та же запись: выбор и снятие отражаются во всех соответствующих группах.
Непривязанные записи остаются в группе «Прочее». Группировка не расширяет исходные
списки, не удаляет записи и не меняет сохранённые исключения.
# Выбор домена с поддоменами

В готовом каталоге у доменов с известными поддоменами доступен общий выбор
«домен + поддомены». Он выбирает точный домен и все записи каталога,
оканчивающиеся на `.<домен>`, включая записи других сервисов. Выбор отдельного
домена сохраняется. Похожие имена без границы точки не включаются.

Это групповой выбор известных записей, а не wildcard-маршрутизация:
неизвестные и будущие поддомены автоматически не охватываются. После
обновления каталога новые записи нужно выбрать и сохранить заново.
Для применения скачайте и переимпортируйте клиентскую конфигурацию.
