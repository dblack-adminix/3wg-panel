# P2P Guard

P2P Guard снижает риск abuse-жалоб по BitTorrent/P2P трафику на VPN-нодах 3WG Core.

## Как это работает

Правила применяются внутри protocol-контейнеров WireGuard и AmneziaWG через `iptables`.

Для каждого контейнера создаётся chain:

```text
3WG-P2P-GUARD
```

Chain подключается к `FORWARD` для VPN-интерфейса (`wg0` или `awg0`). Поэтому фильтрация идёт по уже расшифрованному трафику клиентов.

## Режимы

`soft`:

- блокирует типовые BitTorrent TCP/UDP порты;
- блокирует простые BitTorrent/DHT payload-сигнатуры;
- меньше ломает обычные приложения.

`strict`:

- включает всё из `soft`;
- дополнительно блокирует почти весь UDP от VPN-клиентов;
- оставляет разрешёнными только UDP-порты из настройки, по умолчанию `53,123,443`.

## Ограничения

Это не полноценный DPI. BitTorrent может шифроваться, использовать нестандартные порты и маскироваться под обычный трафик. P2P Guard нужен как practical abuse-control слой, а не как абсолютная гарантия.

Для более строгого контроля используйте:

- `strict` режим;
- лимиты трафика для пользователей;
- блокировку или удаление проблемных peer'ов;
- audit log и Telegram-уведомления.

## В панели

Раздел: `Управление` -> `P2P Guard`.

Доступно:

- включить/выключить P2P Guard;
- выбрать режим `soft` или `strict`;
- задать UDP-порты, разрешённые в strict режиме;
- повторно применить правила после перезапуска VPN-контейнеров;
- посмотреть iptables rules по каждому protocol-контейнеру.

## Что писать в abuse ticket

Пример:

```text
На VPN-ноде включена фильтрация P2P/BitTorrent трафика.
В protocol-контейнерах WireGuard/AmneziaWG применены iptables rules:
- блокировка типовых BitTorrent портов;
- блокировка BitTorrent/DHT payload-сигнатур;
- включён режим strict/soft.

Проблемный peer будет заблокирован при повторном нарушении.
```
