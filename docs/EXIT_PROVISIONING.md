# Минимальные выходные ноды: установка по SSH

В Control откройте «Выходные ноды» (`/exits`). Этот тип отличается от
Core/Easy-нод: на европейском сервере нет веб-панели и пользовательских пиров.

## Установка

1. Подготовьте чистый Debian/Ubuntu с публичным IPv4, root SSH-доступом и
   устройством `/dev/net/tun`. SSH-порт может отличаться от 22.
2. Введите название, IP, SSH-порт и root-пароль.
3. Нажмите «Проверить SSH», сравните SHA256-отпечаток с данными сервера
   (например, `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`).
4. Подтвердите отпечаток и запустите установку. Прогресс сохраняется в журнале.

Проверка отпечатка не использует пароль. При установке ключ повторно
проверяется до аутентификации. Изменение IP/порта сбрасывает подтверждение;
проверка действует 10 минут. Поддерживается только публичный IPv4, не DNS-имя.

Установка создаёт `/opt/3wg-exit`, контейнер `3wg-exit` и служебный агент.
Docker устанавливается только при отсутствии. Используется фиксированный
`54443/udp`; занятый порт или существующий каталог запрещают перезапись.
Другие VPN-интерфейсы, правила host firewall и основной маршрут не заменяются.
Docker при публикации порта добавляет свои правила NAT/forwarding.

## Служебный доступ

Root-пароль остаётся только в памяти запроса/фоновой задачи, не сохраняется в
БД и файлах и не выводится в журнал. Поле пароля очищается после отправки.
Полной гарантии стирания копий строк в памяти Python нет.

Для последующего управления создаётся отдельный SSH-ключ. Его закрытая часть
и конфигурация AWG хранятся зашифрованными существующим NODE_ENCRYPTION_KEY.
В root authorized_keys добавляется только forced-command запись с `restrict`:
она разрешает фиксированные JSON-команды status/restart/stop для `3wg-exit`,
а не произвольный shell, проброс портов или команды Docker. Существующие
SSH-ключи сохраняются; их резерв — `/opt/3wg-exit/authorized_keys.before`.

Изменение SSH-ключа сервера блокирует и дальнейшее служебное управление.
Нужны совместимый OpenSSH с `restrict`, Python 3 и доступ к Docker registry
и пакетным репозиториям. Не передавайте панели root-доступ к ценным серверам
без предварительного резерва.

## Состояния и границы

«Ожидает подключения входа РФ» означает, что контейнер установлен и
служебный доступ проверен. Это **не готовый каскад**: автоматическое
подключение общего входа РФ, назначение выходов пространствам и применение
клиентских маршрутов ещё не реализованы. Связей с РФ установщик не выдумывает.
«Есть handshake» также не заменяет проверку реального выхода в интернет.

При ошибке уже сделанные изменения автоматически не откатываются, чтобы
не удалять данные сервера. Повторная установка существующего IP запрещена.
При перезапуске центра незавершённая операция отмечается как прерванная,
без автоматического повтора; проверьте сервер вручную. Root-пароль для
восстановления потребуется предоставить заново.

Предусмотрены только остановка и перезапуск управляемого контейнера.
Удаление установки выполняется администратором вручную после проверки
зависимостей. Для отзыва служебного ключа удалите только строку с
комментарием `3wg-managed-exit` из authorized_keys — не заменяйте весь файл
старой копией, если после установки добавлялись другие ключи.

Перед обновлением центра сохраняйте БД и `.env` вместе. Пилот РФ → Прага,
созданный ранее отдельно, автоматически не переустанавливается и не
подключается к этому реестру.
